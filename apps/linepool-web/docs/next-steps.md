# 任务清单

> 更新于 2026-11-02。做完一项就把 `[ ]` 改成 `[x]`。
>
> 现状：C 端网站（LP、ONCE）只对接 PC。卡由 SimFlow 开通后交给 PC 托管，客户不接触 eSIM/LPA，只在网站上收短信。PC 和 SimFlow 之间还没打通，所以真实接口要等；在这之前做**不依赖接口、以后也不会白做**的事。
>
> 原则：先列自己平台缺什么，再按上游实际给的接口调整。代码改动每次只做一件、目的明确；不做"整体优化一下"。

## 一、沟通（不写代码）

- [x] 把续费和用量补进 PC 对接清单（[pc-lp-api-checklist.md](pc-lp-api-checklist.md) 的 A9、A10）
- [ ] 把 [pc-lp-api-checklist.md](pc-lp-api-checklist.md) 发给 PC 负责人，请他们按第 9 节的回复表逐项填写
- [ ] 确认 PC 给 C 端的新接口是按这份清单做，还是沿用旧的 v1 文档（两者的 ID 格式、请求头、路径都不一样）
- [ ] 和同事讨论支付与积分，把结论一条一句记下来：
  - [ ] LP 用积分、ONCE 直接付钱，要不要统一？
  - [ ] 1 元兑换多少积分？积分会不会过期、能不能退？
  - [ ] 用户主要在国内还是海外？用哪个支付渠道、哪个公司主体收款？
  - [ ] 开卡或续费失败、用户买错时怎么退？（清单里暂定"续费失败退回积分"）
  - [ ] 代理的钱怎么结算？
  - [ ] 价格谁来定、多久调一次？

## 二、部署测试环境（最优先）

- [ ] 准备一台服务器和测试域名
- [ ] 按 [deploy/README.md](../../deploy/README.md) 部署 LP：Nginx、HTTPS、后端服务、数据库
- [ ] 设置数据库每天自动备份，并试着恢复一次，确认备份真的能用
- [ ] 在手机和电脑上打开测试网站，完整走一遍注册、登录、下单、收短信
- [ ] 记下只在服务器上出现的问题（跨域、Cookie、时区等），交给 AI 修

## 三、上线前的安全检查

- [ ] 运行 `/security-review`，重点看登录、密码重置、会话、限流、越权访问、余额和积分
- [ ] 按检查结果逐项修复，每次只修一项

## 四、上线必需的文字内容

- [ ] 用户协议
- [ ] 隐私政策
- [ ] 退款规则（等第一部分的支付讨论有结论后再定稿）
- [ ] 帮助页和常见问题
- [ ] 自己写初稿，交给 AI 润色后放到网站上

## 五、为接口对接做准备的代码改动

- [ ] ONCE 的价格从代码里写死（7 天 $12、30 天 $35）改成后台可配置
- [ ] LP 续费时长不再写死 7 天和 30 天，改成以接口返回的选项为准
- [ ] 想清楚出问题时在管理后台能不能处理，缺什么补什么：
  - [ ] 短信对不上是哪个客户的
  - [ ] 续费失败要退积分
  - [ ] 用户投诉没收到短信，要查当时的记录

## 六、美化和体验（不急）

- [ ] 用手机把 LP 和 ONCE 各走一遍，把别扭、挤在一起、看不懂的地方记在最下面的"体验记录"里
- [ ] 把记录分成三类：必须改 / 最好改 / 以后再说，再一项项交给 AI 改

- [ ] 注意两条限制：`src/vendor/` 里的上游组件不能改；ONCE 保持现在安静的风格

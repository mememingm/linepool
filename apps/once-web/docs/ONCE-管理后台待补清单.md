# ONCE 管理后台待补清单（修订版）

**本期范围**：上游供应商 API 不接入、不做支付、不做多角色（仍只有一种管理员）。因此本期只做不依赖这三项的功能；号码只能靠后台手动维护，「手动分配」是开通号码的主要方式。

当前后台已有：概览、用户、号码库存、租约、订单、短信记录、Webhook 事件、操作日志；支持禁用/启用账号、重置密码、分配号码、暂停/恢复售卖、延期、回收、重新处理事件，写操作都要填原因并记入日志。

优先级：**P0** 本期先做｜**P1** 本期后半段｜**P2** 有余力再做。

## P0 · 本期先做

### 1. 商品与价格管理
- [ ] 套餐列表：天数、价格、币种、上架/下架、排序
- [ ] 新建 / 编辑套餐；改价不影响已有订单（订单保存下单时的价格）
- [ ] 前台首页、选号页、续费弹窗读取后台套餐，去掉代码里写死的价格（`backend/src/business.ts` 的 `plans`、前端 `src/lib/models.ts` 的 `terms`）

### 2. 号码手动入库与编辑
上游不接入，号码库存只能在后台维护，这一项从「补录」变成必需。
- [ ] 新增单个号码：号码、国家、州/地区、备注
- [ ] 批量导入 CSV：先预览，标出格式错误和重复号码，确认后再写入
- [ ] 编辑号码的地区和备注；删除从未被租用过的号码（租用过的只能停用，保留历史）
- [ ] 号码库存页按地区、区号统计可售数量，库存不足时在概览提醒

### 3. 到期号码处理
- [ ] 「到期保留」号码批量释放 / 批量暂停
- [ ] 冷却期设置：到期后 N 天自动回到可售，或设为永不再售（规则做成后台可配置，业务定了再填）
- [ ] 号码详情显示冷却期剩余时间

### 4. 手动开通补充
- [ ] 分配号码时可选择套餐（读取第 1 项），并可填写线下收款金额和备注，订单按实际金额记录，而不是一律 0 元
- [ ] 用户详情里直接「给此用户开通号码」，不必先去号码库存页找号码
- [ ] 延期时同样可记录金额和备注（区分「补偿赠送」和「线下续费」）

## P1 · 本期后半段

### 5. 用户详情补充
- [ ] 内部备注（只有管理员可见）
- [ ] 登录记录（时间、IP、设备）
- [ ] 修改用户邮箱（记录原邮箱）

### 6. 数据报表
- [ ] 订单数、订单金额（含线下收款）、新用户数的趋势图，按天 / 周 / 月切换
- [ ] 在租号码数、续费率、到期未续数量
- [ ] 热门地区与区号、库存消耗速度（预计多少天卖完）

### 7. 导出
- [ ] 订单、用户、号码库存、操作日志导出 CSV（按当前筛选条件）
- [ ] 短信记录导出单独确认，并记入日志（隐私）

### 8. 客服工单
- [ ] 用户在帮助中心或订单页提交问题，自动关联账号、号码和订单
- [ ] 后台工单列表：待处理 / 处理中 / 已解决
- [ ] 从工单直接跳到用户、订单详情，或发起延期

## P2 · 有余力再做

### 9. 站内公告

### 10. 管理员安全

- [ ] 管理员登录记录
- [ ] 敏感操作（查看或导出短信内容、批量释放号码）二次确认

### 11. 风控视图
- [ ] 可疑账号：短时间大量下单、频繁换号
- [ ] 用户举报处理与封禁记录

## 本期不做

| 功能 | 原因 | 现状处理 |
|---|---|---|
| 真实支付渠道 | 由支付同事接入 | 积分账本、充值/退款状态与演示链路已实现，不能当作真实支付验收 |
| 上游号码采购与续费 | 当前开放 API 未提供这两类接口 | 已完成已持有号码的后台同步、预览和暂停导入；自动采购/续费待新协议联调 |
| 多角色与管理员账号管理 | 不做多角色 | 继续用命令行 `grant-admin` 授权 |

- Webhook 已补未匹配/处理中状态、数据库分页、上游/类型/时间筛选、独立详情、处理记录和安全重试。列表不再携带短信正文。

## 建议顺序

1. **第 1 项 商品与价格**：其他几项（手动开通选套餐、报表金额）都依赖它。
2. **第 2 项 号码入库** 和 **第 4 项 手动开通补充**：这两项决定了没有上游、没有支付时能不能把号码卖出去。
3. **第 3 项 到期处理**。
4. 然后是 P1 的第 5–8 项。

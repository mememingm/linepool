# ONCE 上游接入说明

后台入口：`/#/admin/integrations`；事件处理：`/#/admin/webhooks`。

## 当前已做什么

- 支持配置一个 PingCode 运营账号，保存服务端 API Key 和收信签名密钥。
- 可以检查账号和权限、预览和同步已持有号码、导入时明确归属地区。
- 接收签名收信通知；按事件时间匹配历史租约；查询短信发送结果，兼容既有签名发送回执协议。
- 事件筛选、异常提示、逐次处理记录和安全重试。

**当前 PingCode 开放 API 没有号码采购和上游续费接口。号码同步不会购买、续费或自动开启 C 端付费售卖。支付渠道由支付同事负责。**

## 接入步骤

1. 在承载号码的 PingCode **普通用户账号**中打开「API」，创建 Key。记录账号 ID，授予 `numbers:read`、`sms:read`、`sms:send`。
2. 在 ONCE「上游接入」填写 API 地址（包含部署前缀，以 `/api/open/v1` 结尾）、账号 ID 和 API Key，填写原因后保存。
3. 点击「检查连接」。分别核对账号连接和缺失权限；连接成功只证明认证与权限，不证明短信已经送达。
4. 点击「查看上游号码」。对需要导入的号码明确选择实际地区，再提交导入。导入号码默认暂停，先审核、分配再提供服务；以后可用「刷新已导入号码」更新状态。
5. 将 ONCE 部署为公网 HTTPS，并把 `APP_ORIGIN` 设置为该站点 origin。复制页面上的收信回调地址，在 PingCode「API → Webhook」创建收信通知；将创建时显示的签名密钥保存到 ONCE。
6. 用一个已经映射、具有正确租约的号码做受控收信测试，在事件页核对账号、号码、事件时间、租约和 C 端收件箱。确认归属正确后再扩大范围。

上游管理员 Key 的全平台查询能力不能替代普通用户账号的收信 Webhook。API Key 与 Webhook 签名密钥是不同凭据。普通 `/sms/send` 通过轮询查询发送结果，不要求发送回调；兼容发送回执只能在上游明确支持对应协议时配置。

## 异常怎样处理

| 状态 | 处理 |
|---|---|
| 未匹配 | 核对上游号码是否同步、原租约是否覆盖事件时间，或发送任务是否已保存；修复后重新处理 |
| 失败 | 查看错误原因和处理记录，检查服务后重试；系统也会在上限内自动重试 |
| 已隔离 | 核对内容、号码身份、归属冲突；重试不能绕过校验 |
| 处理中 | 等待完成；超时占用可恢复，不能同时重复人工执行 |
| 已处理 | 查看归属租约或发送任务，不再重复投递 |

重试只重新处理已保存的事件，不采购号码，也不重新发送短信。相同事件 ID 的冲突内容不会覆盖原正文；短信按上游短信 ID 再次去重。处理记录从本次升级开始，旧事件没有补造历史。

## 部署与联调边界

当前配置写入服务端 `backend/.env` 并对当前实例生效；可用 `ONCE_ENV_FILE` 指定持久化文件。多实例部署需要统一配置与密钥管理；不要用旧 `PINGCODE_*` 启动环境覆盖该文件。已有上游号码时，平台地址和账号不能直接切换，需先迁移资源。密钥不返回浏览器，也不写入审计正文。

接入另一个上游前，需取得它的账号鉴权、号码标识/状态/期限、收发短信、验签与重试协议。若要支持自动采购/续费，还必须确认采购幂等键、订单查询、明确失败与未知结果、资源期限，以及退订/释放规则。实现适配器后再接本地号码、租约和积分结算；未知结果保持待核对，不能先交付或重复扣积分。

接口字段和路径见 [ONCE-ADMIN-API.md](ONCE-ADMIN-API.md)。本地验证：后端执行 `npm run test:integrations`，使用一次性本地数据库与 HTTP 模拟上游；此结果不等同于真实上游或生产验收。

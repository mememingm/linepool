# 下级代理管理界面设计方案

> 状态：第一期管理功能及第二期号码、交易往来已实现。
> 范围：完善现有代理工作台，新增下级代理管理模块；不新建另一套后台。
> 实现入口：`/agent/subagents`。新增迁移为 `022_subagent_management.sql`；类型检查、构建和源码完整性检查通过。遵循项目“不运行测试”约束，接口与浏览器业务流程尚未执行验收。
> PC/PingCode 真实采购、分配及支付接入继续暂缓。

## 1. 目标与现状

目标是让一级代理在自己的工作台完成直属下级的创建、查看、维护和状态管理，并逐步接入号码与交易往来。

当前已有基础：

- `src/linepool/agent/AgentShell.tsx`：代理工作台，包含基础的创建下级代理表单和代理列表，但与客户管理混在“主体管理”页。
- `src/linepool/admin/AdminShell.tsx`：平台管理员代理列表、创建代理以及余额流水查看。
- `backend/src/agent-inventory.ts`：代理创建、状态变更、号码转交等业务逻辑。
- `backend/src/agent-inventory-controller.ts`：代理与客户查询、库存和交易相关入口。

主要缺口：独立下级管理入口、分页筛选、详情页、名称编辑、完整状态操作和符合代理权限的往来查询。

## 2. 角色与权限边界

保留现有两级代理结构：

```text
平台管理员
└─ 一级代理
   └─ 二级代理
```

| 身份 | 管理范围 |
| --- | --- |
| 平台管理员 | 全部代理、平台库存、财务与审计 |
| 一级代理 | 直属二级代理、自己的库存及与下级的往来 |
| 二级代理 | 自己的客户、库存、价格、余额和交易 |

约束：

1. 一级代理只能创建和管理直属二级代理。
2. 二级代理使用同一个工作台，但不显示“创建下级代理”；后端同样禁止创建第三级。
3. 上级不默认获得下级全部客户、余额和流水的查看权限。
4. 下级详情中的交易页只展示当前上级与该下级有关的交易，不展示下级完整账本。
5. 名称编辑不能顺带修改绑定用户、上级或层级。
6. 菜单隐藏仅用于交互；所有读写接口均须独立验证身份和归属。
7. 不因实现新页面而扩大现有财务可见范围。现有库存可见规则如需调整，应单独核对，不通过界面改造隐式变更。

## 3. 信息架构与视觉方向

沿用现有后台的字体、表格、按钮、抽屉和状态标签，复用已有组件，不引入另一套设计系统。

```text
代理工作台
├─ 概览
├─ 下级代理          一级代理可见，新增
├─ 我的客户          从原“主体管理”拆出
├─ 我的库存
├─ 价格规则
├─ 我的余额
└─ 交易记录
```

平台管理员现有代理管理继续保留。两端可以复用展示组件，但不得复用管理员的数据权限。

## 4. 页面设计

### 4.1 下级代理列表

建议路由：`/agent/subagents`。

```text
下级代理                                      [新增下级代理]

[搜索名称 / 代理编号] [状态筛选]

代理名称    代理编号    状态    创建时间    操作
华东代理    ……          启用    ……          查看  更多
华南代理    ……          暂停    ……          查看  更多

                              分页 / 每页条数
```

功能：

- 服务端搜索、状态筛选和分页。
- 只列直属下级，不混入当前代理本人。
- 默认不展示下级余额、客户明细。
- 代理编号使用已有代理 ID 的可复制展示形式；一期不增加业务编号生成系统。
- 更多操作包含编辑名称、暂停或恢复。
- 支持加载、空列表、无搜索结果、请求失败和无权限状态。
- 筛选条件变更时回到第一页；详情返回时保留列表查询状态。

当前只有两级，不做层级树。

### 4.2 下级代理详情

建议路由：`/agent/subagents/:id`。

| 页签 | 内容 | 交付阶段 |
| --- | --- | --- |
| 基本资料 | 名称、代理 ID、层级、状态、创建时间 | 第一期 |
| 号码往来 | 当前上级转给该下级的号码、期限及转交时间 | 第二期 |
| 交易往来 | 当前上级与该下级有关的交易 | 第二期 |

操作入口：编辑名称、暂停或恢复；第二期增加转交号码。

规则：

- 未实施的页签不提供假数据或可点击的无效操作。
- “号码往来”是历史转交记录，不等于下级当前库存。
- 号码后续释放或转出时，不得继续标注为该下级当前持有。
- 不提供下级完整客户列表、余额账本入口。
- 直接访问详情 URL 同样需要后端授权，不能依赖列表页过滤。

## 5. 关键操作流程

### 5.1 新增下级代理

一期沿用绑定已有普通账号的方式，不扩展邀请注册系统。

1. 输入已有用户 ID、代理名称。
2. 提示目标账号必须先注册，且未绑定其他代理或客户身份。
3. 后端根据当前登录身份确定上级和层级，不信任前端提供的层级归属。
4. 校验账号可用性、已有绑定关系、当前代理状态和层级。
5. 成功后进入新代理详情页。

不向代理开放全站用户列表。按邮箱查找、邀请链接等能力留待单独设计，避免泄露账号信息。

### 5.2 编辑名称

- 只允许修改直属下级的代理名称。
- 复用现有名称长度等契约约束。
- 服务端验证归属，并记录修改前后内容、操作人和时间。
- 不开放修改绑定用户、代理层级、上级归属。

### 5.3 暂停与恢复

建议一期规则：

- 一级代理可以暂停、恢复直属下级。
- 必须填写原因，记录操作人、时间和前后状态。
- 暂停撤销目标代理的登录会话，并持续在后端限制访问，不能仅清理一次会话。
- 暂停不自动收回号码、不清空余额、不删除历史记录。
- 恢复代理状态不应覆盖普通用户账号自身的禁用状态。
- 终止代理暂由平台处理；涉及余额、库存处置的规则明确前，不向上级开放。
- `TERMINATED` 不应被普通“恢复”按钮当作暂停处理。

确认弹窗需明确说明暂停影响，禁止使用模糊的“确定操作吗”。

### 5.4 转交号码（第二期）

从自己的可转交库存中选择号码：

1. 接收方固定为当前详情页对应的直属下级。
2. 显示原有效期，转交期限不得超过原持有期限。
3. 提交前确认号码、接收方和期限。
4. 服务端再次验证双方状态、归属、可用性与有效期。
5. 成功后原持有关系退出，号码不再计入上级自己的可售库存。
6. 生成可追溯的转交记录。

当前后端转售记录金额为 0，因此一期接入时使用“转交号码”，不得描述为已完成计费的销售。自动定价、扣款和结算另立范围。

余额转移如需纳入，须先明确资金流向和权限，再接入页面；不默认允许上级扣减下级资金。

## 6. 技术实施范围

### 6.1 前端

- 在现有 `src/linepool/agent/` 下拆分列表、详情和操作表单，避免继续向 `AgentShell.tsx` 堆积全部业务。
- 更新 `src/linepool/agent/navigation.ts` 及路由识别，支持列表和动态详情地址。
- 获取当前代理身份、层级及可执行操作，区分一级、二级菜单。
- 按当前页面加载资源，不再以一次全量加载作为所有页面的共同依赖。
- 每个操作具备提交中状态、防重复点击、失败提示及成功后数据刷新。
- 网络超时重试沿用原操作的幂等键，不因重试重新生成业务操作。
- 错误信息使用业务提示；不要将可处理的状态冲突统称为“服务不可用”。

### 6.2 后端与契约

复用已有创建、状态变更和号码转交逻辑，补齐以下能力：

| 能力 | 要求 |
| --- | --- |
| 当前代理上下文 | 返回身份、层级和页面所需能力信息，不替代服务端鉴权 |
| 直属下级列表 | 服务端限定直属关系，支持搜索、状态筛选、分页及稳定排序 |
| 下级详情 | 验证直属关系，仅返回允许展示的资料 |
| 名称修改 | 校验归属、输入及审计，不允许变更层级关系 |
| 状态控制 | 核对状态转换、暂停后登录和旧会话行为 |
| 号码往来 | 查询双方转交历史，区分历史归属与当前归属 |
| 交易往来 | 限定当前双方相关记录，不返回下级完整账本 |

具体接口路径在实施时按已有 `/agent-inventory` 契约统一，不在本方案中假定新接口已经存在。

数据库变更按实际缺口追加迁移；不修改已经应用的历史迁移，不为列表展示增加不必要的业务表。

## 7. 分期交付

### 第一期：管理闭环

- 独立下级代理入口。
- 列表、搜索、筛选和分页。
- 新增、详情、名称编辑。
- 暂停、恢复和审计。
- 一级、二级菜单及后端权限验证。
- 将客户管理从主体管理中拆出，保留已有客户功能。

### 第二期：业务往来

- 从下级详情页转交号码。
- 号码往来记录。
- 双方交易记录。
- 如需余额转移，先确认资金流向规则再实施。

### 暂不包含

- 三级或无限层级代理。
- 邀请注册、批量开户。
- 更换上级、转移账号绑定。
- 自动计费转售、返佣、真实支付。
- PC/PingCode 真实采购与分配。
- 自动回收库存、清空余额或删除历史数据。

## 8. 验收标准

使用平台管理员、两个不同一级代理及各自二级代理账号验证，不以页面静态展示作为完成标准。

### 权限

- 一级代理只能管理自己的直属下级。
- 修改 URL、代理 ID 或请求参数不能越权访问其他代理。
- 二级代理不能创建第三级，直接调用接口也会被拒绝。
- 上级看不到下级无关客户信息和完整财务账本。
- 代理不能调用管理员库存录入、余额调整等专属操作。

### 管理行为

- 重复点击或网络重试不会重复创建代理。
- 账号已绑定、账号不可用、名称不合法时给出明确提示。
- 搜索、状态筛选、分页及详情返回行为正确。
- 编辑名称和状态变更有审计记录。
- 暂停后旧会话失效，重新登录或直接调用接口不能绕过限制。
- 恢复不会绕过用户账号自身的禁用状态。
- 暂停、恢复不误改库存归属、余额或历史流水。

### 第二期业务

- 转交失败时没有部分成功，库存和记录保持一致。
- 重复请求不会重复转交号码。
- 不能转交他人库存、不可用库存或超出有效期的号码。
- 转交成功后，双方库存归属与历史记录一致。
- 号码后续释放、转出后，历史转交记录仍准确，不冒充当前库存。

### 验证方式

- 前后端类型检查及构建。
- 针对身份、直属关系、状态和幂等性的接口测试。
- 使用隔离测试数据库验证事务与数据一致性，不对真实业务库存做破坏性测试。
- 浏览器实际执行创建、查看、修改、暂停及恢复流程；第二期再验证转交流程。

## 9. 实施建议

先完成第一期，再接入号码与交易往来。先确保“谁能管理谁”的边界正确，再扩展库存与资金动作，避免将管理、库存和计费一次混在一起。

## F1：只卖美国号码，前台、后台、接口规则一致

### 现状
- 前端用 4 处分散的 `'us'` 写死了美国：
  - `src/linepool/workspace-reference/sale-catalog.ts:4`：`saleOffers` 只保留美国套餐，地区页和首页卡片都用它
  - `PurchasePage.tsx:42`：恢复购买草稿时，国家强制设为 `us`
  - `PurchasePage.tsx:77`：判断平台是否可买时，只看美国套餐
  - `PurchasePage.tsx:106-108`：选择平台后自动选美国
- **后端不限制国家**：
  - 下单接口（`backend/src/ordering.ts`）按传入的国家处理，直接调接口可以买到英国号。
  - 目录接口返回 6 个国家的套餐和库存。
- 用户能看到的结果：地区页把英国等 5 国显示为“可用库存 0 个 / 暂无短期服务”，看起来像是缺货，而不是没开放。
- 管理员能看到的结果：
  - 后台“商品管理”把这些国家的套餐显示为“销售中”，并显示库存（N8），实际上前台买不到。
  - 管理员可以把新加坡等号码手动分配给用户（N7）。

### 方案

1. **把“前台开放国家”收拢成一个配置**
   - 在 `packages/contracts` 中新增常量 `storefrontRegionIds = ['us'] as const`，前后端共用。
   - 前端 4 处 `'us'` 全部改为引用这个常量（“指定区号”仍然只在美国显示，保留 `region === 'us'` 的判断，加注释说明区号功能是美国专属）。
   - 以后要开放其他国家，只需要改这一处配置，再按第 6 点去掉单国自动选择。

2. **后端下单校验**
   - `ordering.ts` 创建订单时，如果国家不在 `storefrontRegionIds` 里，返回 `409 REGION_NOT_AVAILABLE`。
   - 前端文案：“该地区暂未开放购买”。
   - 续费接口（如果涉及国家）也加同样的校验。

3. **用户端地区页**
   - 美国正常显示。
   - 其他国家显示灰色的“即将开放”标签，**不显示库存数和价格**，也不显示“创建服务”按钮。
   - 不再显示“0 个 / 暂无短期服务”。

4. **用户端购买页**
   - 第 2 步“国家与区号”保持只有美国，并且自动选中。
   - “目前仅支持美国号码”改为“目前开放：美国。其他地区即将开放”。

5. **管理后台**
   - **商品管理**：不在开放国家里的套餐，状态列显示“前台未开放”（灰色），不再显示“销售中”；国家分组标题旁加同样的标签。
   - **创建 / 编辑商品**：选择非开放国家时，表单顶部提示“该国家前台暂未开放，保存后用户也无法购买”。
   - **手动分配号码（N7）**：仍然允许分配非美国号码，因为管理员有时需要补发或测试；但弹窗里要提示“该国家前台未开放，用户无法自行购买同国家号码”。
   - **概览页“可售号码”**：只统计开放国家，旁边注明“仅统计前台开放的地区”。

6. **以后开放更多国家时**（本次不做，只记录）
   - 修改 `storefrontRegionIds`；
   - 购买第 2 步改为列出所选平台下有在售套餐的国家，只有一个国家时自动选中。

### 验收
- 用户端：地区页只有美国可点，其他国家显示“即将开放”；购买流程和现在一样能买美国号。
- 用接口直接提交英国订单，返回“该地区暂未开放购买”，并且不扣积分。
- 后台商品管理里，英国等国家的套餐显示“前台未开放”。
- 管理员手动分配新加坡号码时，弹窗里有提示，并且仍然可以完成分配。
- 代码中除区号逻辑以外，不再有分散写死的 `'us'`。

## F3：错误提示全部变成中文、看得懂的话

### 现状
- 用户端的错误文案在 `src/linepool/workspace-reference/workspace-data.ts` 的 `apiMessage` 里按错误码翻译。
- 不认识的错误码会**直接显示后端的英文原文**（第 50 行 `?? error.message`）。
- 走查中碰到的例子：账号被禁用后登录，中文界面显示 `Account is disabled`。

### 方案
1. **补齐用户会碰到的错误码**，例如：
   - `ACCOUNT_DISABLED`：账号已被停用，如有疑问请联系客服
   - `RATE_LIMITED`：操作太频繁，请稍后再试
   - `FORBIDDEN`：你没有权限进行此操作
   - `REGION_NOT_AVAILABLE`（F1 新增）：该地区暂未开放购买
2. **兜底规则改为不显示英文原文**：
   - 4xx 错误统一显示“操作未完成，请检查后重试（错误码 XXX）”。
   - 5xx 错误保持现在的“服务暂时不可用”。
   - 错误码保留在括号里，方便用户截图反馈时定位问题。
3. 代理端 `src/linepool/agent/subagent-shared.tsx` 的 `agentError` 已经是中文兜底，只需要补上新增的错误码。管理端同样检查一遍。
4. 把后端所有 `ApiFailure` 用到的错误码导出成一张表，逐个确认用户、代理、管理员三端都有中文和英文文案。

### 验收
- 被禁用的账号登录时显示“账号已被停用，如有疑问请联系客服”。
- 切换到英文界面后重复上面的操作，显示对应的英文文案。
- 找一个没有翻译的错误码触发一次，看到的是“操作未完成……（错误码 XXX）”，而不是英文原文。

## F4：管理员订单筛选只保留 4 个真实状态

### 现状
- 订单页的“状态”下拉里有 7 项：已完成、开通处理中、开通失败、已取消、**结算待核对、异常订单、今日订单**。
- 后三项不是订单状态：
  - “今日订单”是时间条件；
  - “异常订单”是“开通失败，或积分扣款记录缺失”；
  - “结算待核对”是另一个核对条件。
- 它们都塞进了 `status` 参数，原因是概览页的快捷入口用 `?status=today`、`?status=EXCEPTION` 跳转到订单页：
  - 前端：`src/linepool/admin/AdminShell.tsx:374, 758, 764`
  - 后端：`backend/src/administration.ts:111-113`

### 方案
1. **状态下拉只保留 4 项**：处理中、已完成、失败、已取消。文案和用户端保持一致。
2. **新增独立的“快捷筛选”标签**，放在状态下拉旁边：
   - `全部`、`今天`、`需要处理`
   - “需要处理”合并原来的“异常订单”和“结算待核对”，并在标签上显示数量，例如“需要处理 2”。
   - 快捷筛选和状态下拉可以叠加，例如“今天 + 失败”。
3. **URL 参数分开**：
   - 例如 `?status=FAILED&view=today`、`?view=attention`。
   - 后端订单查询新增 `view` 参数（`today` | `attention`），`status` 只接受 4 个状态值，契约同步修改（`packages/contracts/src/admin.ts`）。
   - 旧链接 `?status=today` / `?status=EXCEPTION` 自动转换为新参数，不报错。
4. 概览页“今日订单”和“笔订单需要核对”改为跳转到 `?view=today` / `?view=attention`。

### 验收
- 状态下拉只有 4 项。
- 在概览页点“今日订单”，跳到订单页后“今天”标签处于选中状态，状态下拉仍然是“全部状态”。
- “需要处理”能列出开通失败的订单，以及缺少扣款记录的订单，数量和概览页一致。
- 打开旧链接 `/admin/orders?status=EXCEPTION`，页面正常显示“需要处理”的结果。

## F5：一级代理能方便地给下级转余额

### 现状
- 二级代理拿号要从余额扣款。
- 财务页的“转移余额”其实**支持转给直属下级**（选项写着“选择直属客户或下级”），但是：
  - 下级详情页看不到对方的余额，也没有转账入口；
  - 转交号码时对方余额不足，只提示余额不足，不告诉一级代理可以去哪里给下级充值；
  - 转给客户的美元余额，客户用不上（客户买号用积分，两套账不通，对应 A6）。

### 方案
1. **下级详情页**（`src/linepool/agent/SubagentDetail.tsx`）：“基本资料”中增加“账户余额：USD X”，旁边放“转余额给 TA”按钮。点击后打开转账弹窗，接收方已经预先选好。
2. **转交弹窗**（库存页和下级详情页都要改）：下级余额不足时，提示改为“对方余额不足：需要 X，当前 Y”，后面附“给 TA 转余额 →”按钮。转账完成后回到原来的转交弹窗，已经填写的内容保留。
3. **财务页**（`src/linepool/agent/pages/FinancePage.tsx`）：
   - “转移余额”的接收方下拉**只列直属下级，不列客户**（决定 4）。
   - 按钮文字改为“转余额给下级”。
   - 没有直属下级时（例如二级代理），隐藏这个按钮。
   - 后端转账接口同步拒绝接收方为客户的请求，防止有人绕过前端直接调用。

### 验收
- 一级代理在下级详情页点“转余额给 TA”，转 5 USD 后，详情页余额立即更新，双方财务流水各有一条记录。
- 下级余额不足时转交号码，提示里可以直接去转余额，转完后回到原来的转交弹窗继续操作。
- 财务页的接收方下拉里没有客户；直接调接口转给客户会被拒绝。
- 二级代理的财务页没有“转余额给下级”按钮。

## F6：下级详情页的转交弹窗（核对）

### 现状
- 走查时，下级详情页的“转交号码”弹窗没有使用时长和金额，并且漏出一个英文的 “Close”。
- 之后另一个会话修改了 `src/linepool/agent/SubagentActions.tsx`，最新代码中已经接入使用时长和结算报价（`useSettlementQuote`）。

### 方案
- 按下面 4 条验收，不重复开发：
  1. 选号码后出现使用时长，并显示金额；
  2. 余额不足时不能提交（并且有 F5 的转余额入口）；
  3. 关闭按钮的文字是中文；
  4. 按钮文案统一用“转交”，不出现“分配”（A4）。
- 如果仍有差异，把它改成直接复用库存页的转交弹窗，并预先选好接收方，避免以后两套逻辑又不一致。

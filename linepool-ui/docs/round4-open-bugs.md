# 第四轮及走查遗留功能 / Bug 汇总

依据 `full-walkthrough-2026-10-28.md` 第七节及前六节整理。这里只列项目需要修改或决策的内容，不记录 agent 协作过程。

## P0 / 阻断

### 1. 暂停代理仍可转余额（Q1）
- **现象**：暂停小李代理后，转号码被拒绝 `409 AGENT_NOT_ACTIVE`，但余额转账仍返回 `201 COMPLETED`。
- **影响**：暂停状态下仍可发生结算。
- **修改**：余额转账与号码转交统一校验目标代理为 `ACTIVE`；补接口、幂等和暂停状态测试。

### 2. 源码、编译产物、数据库迁移版本不一致（Q2）
- **现象**：公开 schema 只有 028/029 时，运行代码读取 `number_allocations.agent_entitlement_id` / `provided_by`，导致 numbers、dashboard、匹配短信返回 500。
- **修改**：统一源码、`dist`、迁移版本；禁止通过直接修改 `dist` 绕过。启动检查应覆盖 numbers、dashboard、webhook smoke。
- **决策**：明确是执行 030 迁移，还是撤回依赖 030 的源码；不能两者都保持半成品状态。

### 3. 客户链路缺陷（C1/C2）
- 代理分配给客户的号码必须在客户工作台显示。
- 代理库存号码的短信必须能按归属路由到客户收件箱。
- 当前代理/客户持有短信仍为 `UNMATCHED`，需按产品方案决定并实现第二条匹配路径。

### 4. 用户购买与积分闭环（U1/U2/M2）
- 购买页不能写死只显示美国，必须与目录、库存和商品配置一致。
- 新用户没有积分获取途径；管理员需要“调整积分”（数量、增减、原因、流水、审计）。
- “只售美国”若是最新产品决策，则应统一后端目录、前端展示、后台手动分配规则，不能只改前端文案。

## P1 / 重要功能问题

### 5. 客户/代理权限边界不一致（Q4）
- 普通客户 `GET /api/agent-inventory/holdings` 当前能返回自己的客户号码（200），方案预期为 403。
- 需要产品确认：客户是否允许查看自己的代理分配号码；确认后统一接口、页面入口和测试计划。

### 6. 暂停客户时普通工作台稳定性（Q3）
- 暂停小王代理业务期间，`/numbers`、`/dashboard/overview` 曾返回 500；客户 holdings 仍能返回自己的号码。
- 预期：暂停代理分配不应影响普通用户自己的号码、积分、订单和短信工作台。
- 需要在真实迁移/数据库版本一致的环境中补回归。

### 7. 恢复代理后的会话处理（Q5）
- 暂停会清除代理 session；恢复后旧 cookie 仍 401。
- 需要明确产品行为：要求重新登录，或恢复后提供明确提示/自动刷新；补完整恢复后工作台测试。

### 8. 错误码约定不一致（Q6）
- 创建三级代理实际返回 `409 MAX_AGENT_LEVEL`，测试计划预期 `403 SUBAGENT_MANAGEMENT_REQUIRED`。
- 统一能力不足、层级上限、资源不可见等错误码语义，并同步前端提示与测试方案。

### 9. F5/F6 实际流程尚未验收
- F5/F6 目前只有类型检查，余额转移、号码转交/回收、前端参数和错误处理尚未在独立数据库/服务窗口实测。
- 必须先完成 contracts → controller → SQL → 前端调用链静态核验，再在批准的隔离环境执行真实接口回归。

### 10. 统一库存 030 迁移未完成决策
- `030_unified_number_inventory.sql`、`unified-agent-stock.ts` 的归属、批准状态、字段契约和回滚边界必须明确。
- 未批准前不得迁移、改库或继续依赖新字段。

## P2 / 体验与一致性

- Q5 之外的代理 session/状态提示需统一。
- 首页、购买页、地区页、后台的库存口径需统一。
- 代理概览信息过载、术语和交易类型筛选不一致。
- 管理操作代码需翻译为用户可读中文，并显示正确操作人身份。
- 手机端号码/库存页面需改为可读卡片布局。
- 英文界面未翻译项需补齐。
- 订单应显示国家、平台、期限；号码需支持详情和续期。
- 禁用、回收、上架/下架提示和原因选项需统一。

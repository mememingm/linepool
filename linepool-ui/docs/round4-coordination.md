# 第四轮协作与环境协调记录

> 本文件只记录 agent 分工、文件归属、环境状态、变更批准和阻塞；测试结论与用例证据只写入 `full-walkthrough-2026-10-28.md` 第七节。后续执行顺序见 `round4-recovery-plan.md`。

## 一、强制协作规则

1. **单一负责人**：开发、测试、环境分别指定负责人；超出范围必须先上报，不得自行扩展。
2. **单文件单写者**：同一时间一个文件只能由一个 agent 修改；前台、后端、迁移分别维护文件清单。
3. **测试冻结代码**：测试窗口禁止修改 `backend/` 和数据库。开发必须使用独立 sandbox 数据库与端口。
4. **环境单一负责人**：只有环境负责人可以启动、停止服务、执行迁移；其他 agent 只读检查并报告。
5. **禁止修改编译产物**：源码与数据库版本不一致时，暂停并提交“执行迁移 / 撤回代码”的决策，不得直接修改 `dist/`。
6. **运行验收**：撤回必须与已提交基线比较；修复必须实际调用接口验证，typecheck 和 diff-check 不能替代运行验收。
7. **记录分离**：本文件记录协调；`full-walkthrough-2026-10-28.md` 只记录测试结论、问题和证据。

## 五、最近一次编排故障总结

1. Crew 任务创建成功，但 `work({ autonomous: true })` 多次因 `spawn EINVAL` 无法拉起 worker；随后自动 continuation 重试 3 次，0/4 任务产生进展。
2. 由于 Crew 未成功分配 worker，协调会话误用 `task.start` 把 task-1～task-3 指派给自己；该错误已停止，相关任务已做行政阻塞，未执行代码、测试或环境操作。
3. 后续新建的 task-5～task-7 虽声明 role=`worker`，Crew 仍返回 `spawn EINVAL`；不能把“创建任务”当作“已安排同事执行”。
4. 正确替代路径是由项目负责人手动指定真实 agent/会话，再执行任务；协调会话只负责任务拆分、文件边界、状态记录和验收汇总，不直接执行同事任务。
5. 当前未因该故障启动/停止服务、迁移、改库或修改源码；已启动的只读委派属于独立会话，结果应单独验收，不等同于 Crew 任务完成。

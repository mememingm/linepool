# LINEPOOL 代理中心重构方案

> 状态：方案确认稿（待按此方案重新实现）  
> 目标：纠正当前代理功能定位、入口和界面方向。  
> PC/PingCode 真实采购、同步和支付暂不纳入本阶段。

## 1. 需求纠正

当前实现的问题不是简单的“代理页面不好看”，而是产品角色和入口设计偏了：

- 代理不应该登录后直接进入一套独立、简化的代理工作台。
- 代理首先仍然使用普通用户工作台；只有具备代理身份的账号才显示“代理中心”入口。
- 点击“代理中心”后，进入与平台管理后台同一套视觉和交互体系的代理管理界面。
- 当前平台管理后台的库存、代理、订单、余额等能力，应拆分为平台权限和代理权限，而不是重新设计一套完全不同的页面。
- 当前测试账号显示为“1级代理”，不能继续把它当作普通的下级代理测试账号使用；测试数据必须明确层级和归属。

## 2. 业务角色模型

### 2.1 平台管理员

LINEPOOL 内部运营人员，使用 `/admin`。

负责：

- 管理平台用户和代理账号；
- 导入或维护平台号码库存；
- 将库存分配给合作伙伴代理；
- 配置平台商品、服务和基础价格；
- 查看全平台订单、流水、利润和接码数据；
- 处理代理状态、余额调整和异常记录。

### 2.2 合作伙伴代理（一级代理）

平台直接合作的代理商，使用普通工作台中的“代理中心”入口。

负责：

- 管理自己的客户；
- 查看平台分配给自己的号码库存；
- 设置自己的销售价格；
- 创建和管理直属下级代理；
- 将号码、额度或商品能力分配给直属下级代理；
- 查看自己的订单、流水、收入、成本和利润；
- 查看直属下级的业务汇总，但不能查看平台全部数据。

### 2.3 下级代理（二级代理）

由合作伙伴代理创建或绑定的下级代理。

负责：

- 管理自己的客户；
- 使用自己持有的库存；
- 设置面向客户的销售价格；
- 查看自己的订单、流水、接码量和利润；
- 接收上级分配的号码或额度。

不允许：

- 创建新的代理；
- 查看其他代理的数据；
- 查看上级的完整利润、成本和余额；
- 直接操作平台库存；
- 修改平台商品和平台基础价格。

### 2.4 普通用户

继续使用现有普通用户工作台：

- 购买服务；
- 查看自己的号码；
- 查看短信和接码记录；
- 查看订单、积分和账户设置。

普通用户没有代理身份时，不显示“代理中心”。如果一个账号同时具备普通用户身份和代理身份，则默认先进入普通用户工作台，再通过入口进入代理中心。

## 3. 页面入口和路由

### 3.1 普通用户工作台

保留现有界面和结构，例如：

- `/app/dashboard`
- `/app/purchase`
- `/app/inbox`
- `/app/numbers`
- `/app/orders`
- `/app/points`
- `/app/settings`

```text

```

代理账号登录后不自动跳到 `/agent`，而是进入普通工作台。点击“代理中心”后进入代理管理界面。

### 3.2 代理中心

建议继续使用 `/agent` 路由，但改为复用后台管理布局：

- `/agent/dashboard`
- `/agent/agents`
- `/agent/customers`
- `/agent/inventory`
- `/agent/products`
- `/agent/orders`
- `/agent/finance`
- `/agent/reports`
- `/agent/settings`

代理中心顶部应显示：

```text
LINEPOOL 代理中心
当前身份：合作伙伴代理 / 下级代理
返回普通工作台
```

### 3.3 平台后台

继续使用 `/admin`，但在后台中增加统一的数据看板和财务分析：

- `/admin/dashboard`
- `/admin/users`
- `/admin/agents`
- `/admin/inventory`
- `/admin/products`
- `/admin/orders`
- `/admin/finance`
- `/admin/reports`

## 4. 界面方向

### 4.1 代理中心不再使用当前简化版界面

当前 `AgentShell.tsx` 的浅色大标题、简单页签和表格结构不作为最终方向。代理中心应：

- 复用 `AdminShell.tsx` 的侧边栏、顶部栏、面包屑、页面容器和表格组件；
- 保持截图中的后台信息密度和操作方式；
- 通过权限控制隐藏或禁用功能，而不是为代理重新制作完全不同的 UI；
- 统一使用后台的按钮、筛选器、弹窗、分页、状态标签和数据卡片。

### 4.2 合作伙伴代理界面

合作伙伴进入后看到与后台相似的菜单：

```text
代理概览
代理管理
客户管理
库存管理
商品与价格
订单管理
财务流水
数据报表
```

但隐藏：

- 平台用户管理；
- 平台号码导入；
- PC/PingCode 配置；
- 平台全局商品设置；
- 平台级余额调整；
- 全部代理数据。

### 4.3 下级代理界面

下级代理看到：

```text
代理概览
客户管理
我的库存
商品与价格
我的订单
我的财务
数据报表
```

隐藏：

- 代理管理；
- 平台库存导入；
- 上级和其他代理信息；
- 平台级配置。

## 5. 代理概览页设计

### 5.1 合作伙伴代理概览

顶部 KPI 卡片：

- 当前余额；
- 可用库存；
- 已分配库存；
- 直属下级代理数量；
- 客户数量；
- 今日销售额；
- 今日利润；
- 今日接收验证码数量。

图表区域：

1. **销售额、成本、利润趋势**
   - 支持今日、近 7 天、近 30 天；
   - 销售额 = 客户实际支付金额；
   - 成本 = 上级结算价或平台成本；
   - 利润 = 销售额 - 成本。

2. **近期接码数量**
   - 按小时或按天显示；
   - 数据来源为有效号码对应的短信接收记录；
   - 支持按平台筛选，如 WhatsApp、Telegram、Google。

3. **库存状态分布**
   - 可售；
   - 已分配给自己；
   - 已分配给下级；
   - 已使用；
   - 已过期；
   - 异常。

4. **平台/服务销售排行**
   - 服务名称；
   - 销售数量；
   - 销售额；
   - 利润。

5. **下级代理经营概览**
   - 下级代理名称；
   - 销售额；
   - 接码量；
   - 当前库存；
   - 利润；
   - 最近活跃时间。

### 5.2 下级代理概览

下级代理只看到自己的数据：

- 今日销售额；
- 今日利润；
- 当前库存；
- 客户数量；
- 今日订单数；
- 今日接码量；
- 销售额和利润趋势；
- 服务销售分布；
- 最近订单和最近接码记录。

不能看到上级代理的总体利润和其他下级代理数据。

### 5.3 平台管理概览

平台管理员看到全局数据：

- 平台总销售额；
- 平台总成本；
- 平台总利润；
- 代理结算金额；
- 活跃代理数量；
- 活跃普通用户数量；
- 可用库存和库存预警；
- 近期接码总量；
- 各服务销售排行；
- 各代理销售和利润排行；
- 异常订单、过期资源和同步冲突。

## 6. 主要业务流程

### 6.1 平台分配库存给合作伙伴

```text
平台导入/维护库存
    ↓
平台选择合作伙伴代理
    ↓
设置持有期限和结算价格
    ↓
库存归属合作伙伴代理
    ↓
记录分配流水和平台成本
```

### 6.2 合作伙伴分配给下级代理

```text
合作伙伴查看自己的可分配库存
    ↓
选择直属下级代理
    ↓
设置分配期限和代理结算价
    ↓
库存归属下级代理
    ↓
记录上级成本、下级成本和转交流水
```

### 6.3 代理销售给普通用户

```text
普通用户进入购买服务
    ↓
系统识别其所属代理/销售主体
    ↓
使用该代理的销售价格
    ↓
扣除用户余额或积分
    ↓
创建订单并分配号码
    ↓
记录代理收入、成本和利润
```

### 6.4 接码和利润统计

```text
短信接收记录
    ↓
校验号码、服务、有效期和归属
    ↓
关联订单、代理、客户和服务
    ↓
写入接码统计
    ↓
更新代理和平台数据看板
```

## 7. 财务和利润口径

所有页面必须统一以下口径：

```text
销售额 = 普通用户实际支付金额
成本 = 上级代理或平台提供的结算成本
毛利润 = 销售额 - 成本
利润率 = 毛利润 / 销售额
```

如果当前没有真实 PC 成本数据，不允许伪造成本。应显示：

- `成本待同步`；或
- `本地模拟成本`；或
- `暂不计算真实利润`。

平台、合作伙伴代理和下级代理使用不同的成本层级：

```text
平台成本 → 合作伙伴结算价 → 下级代理结算价 → 普通用户销售价
```

每次价格或库存转交都必须保留价格快照，不能因为后续修改价格而改变历史订单利润。

- order_count
- sales_amount_minor

- profit_amount_minor

## 12. 验收标准

### 入口

- 普通用户登录后看到原普通工作台；
- 代理账号登录后也先看到普通工作台；
- 只有代理账号显示“代理中心”；
- 点击后进入后台风格的代理界面；
- 普通用户无法通过 URL 越权进入代理中心。

### 层级

- 一级代理可以看到并管理直属下级；
- 二级代理看不到代理管理菜单；
- 二级代理无法创建三级代理；
- 代理只能访问自身及允许范围内的数据。

### 业务

- 平台可以分配库存给合作伙伴；
- 合作伙伴可以分配给直属下级；
- 下级代理可以将库存用于普通用户订单；
- 每一次分配、销售、接码和结算都有流水；
- 历史利润不因价格修改而变化。

### 看板

- 平台、合作伙伴、下级代理看到不同范围的数据；
- 销售额、成本、利润口径一致；
- 接码量可以追溯到短信记录；
- 没有真实 PC 成本时不展示虚假的真实利润。

## 13. 本方案的最终产品结构

```text
平台管理员后台
        │
        │ 分配库存、设置基础价格、管理合作伙伴
        ▼
合作伙伴代理中心
        │
        │ 创建下级代理、分配库存、设置代理价格
        ▼
下级代理中心
        │
        │ 管理客户、销售服务、查看利润
        ▼
普通用户工作台
        │
        │ 购买号码、接收短信、查看订单
        ▼
短信/接码记录与财务流水
```

最终原则：

> 普通用户工作台是统一入口；代理中心是普通工作台上的一种增强身份能力；代理中心沿用后台管理的视觉和交互体系；不同代理层级只通过权限、数据范围和菜单差异区分，而不是重新做一套割裂的产品。

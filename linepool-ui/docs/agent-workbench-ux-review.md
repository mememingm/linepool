## 二、已修复的问题

### 1. 库存管理页无法加载（阻断）

- **现象**：`/agent/inventory` 只显示“请求未完成，请稍后重试。”
- **原因**：接口都返回 200，但前端合约 `numberHoldingSchema` 要求每条号码带 `sourceTxOrderId` 字段，而后端两处号码序列化代码都没有输出这个字段。前端校验失败，抛出 `INVALID_RESPONSE`。受影响的接口包括 `/agent-inventory/holdings` 和 `/agent-inventory/transferable-holdings`，以及所有通过 `mapHolding` 返回号码的接口（分配、转交、领取等）。
- **修改**：`backend/src/agent-inventory.ts`
  - 持有列表查询的结果映射（约第 508 行）补充 `sourceTxOrderId: row.source_tx_order_id`
  - `mapHolding()`（约第 1129 行）补充同一字段

### 2. 分配号码给客户几乎一定失败（阻断）

- **现象**：点击“核对分配信息 → 确认分配”后，提示“转交开始时间不能早于原持有开始时间。”。但界面上填的开始时间明明在持有期内。
- **原因**：
  - 弹窗打开时，默认开始时间是“当前时间 + 1 分钟”。`datetime-local` 输入框只精确到分钟，秒数被截掉。
  - 用户走完“核对 → 确认”两步通常超过 1 分钟，提交时这个开始时间已经过去。后端校验 `startsAt < now` 后返回 `HOLDING_WINDOW_INVALID`。
  - 同一个错误码在前端被映射成“不能早于原持有开始时间”，所以提示和真实原因不符。
- **修改**：`backend/src/agent-inventory.ts` 中的 `assignHoldingToCustomer`
  - 开始时间如果早于当前时间，按“立即开始”处理：`startsAt = max(input.startsAt, now)`
  - 删除多余的 `startsAt < new Date()` 拒绝条件；“不得早于原持有开始时间”的校验保留
  - 幂等校验仍然使用原始的 `input`，重放请求不受影响

### 3. 订单类型标错

- **现象**：分配号码给客户产生的订单，在订单列表里显示为“余额充值 / 扣减”。
- **原因**：后端给这类订单生成的单号前缀是 `LP-A-`，与余额调整共用。前端 `txKindLabel` 只看单号前缀来判断类型。
- **修改**：
  - `src/linepool/admin/primitives.tsx` 的 `txKindLabel`：前缀为 `A` 且 `kind === 'TRANSFER'` 时显示“号码分配给客户”。余额调整的 `kind` 是 `ADJUSTMENT`，两者不会混淆，历史订单也能正确显示。
  - `src/linepool/i18n/admin-messages.ts`：新增英文文案 `Number assigned to customer`

### 4. 订单“对方”列显示成自己

- **现象**：平台分配给我的号码订单，“对方”一列显示“测试下级代理（我）”。
- **原因**：这一列固定显示买方，而平台分配号码时买方就是自己。
- **修改**：`src/linepool/agent/pages/OrdersPage.tsx`：买方是自己时改为显示卖方，因此平台分配的订单显示为“平台”。

# LINEPOOL 客户端功能补全清单

## 1. 目标

以现有 LINEPOOL 客户后台为功能参考，在 `platform/apps/web` 中补齐客户侧前端能力。

当前阶段继续使用本地 API、PostgreSQL 和 mock 数据，不接入公司真实接口。需要真实公司能力的功能通过独立适配层隔离，后续拿到 API 文档后替换数据源，不重写页面和交互。

## 2. 实施边界

- 保留现有 Vue 3、TypeScript、Vue Router、Pinia 和 Element Plus 技术栈。
- 优先复用已经完成的本地 API 和数据库能力。
- 现有 API 暂不支持的能力使用明确标注的 mock service，不伪装成生产数据。
- 不接入真实支付、真实短信采集、设备端、eSIM 或管理员后台。
- 不查看、获取、下载或生成 eSIM 二维码及激活码。
- 保留现有未提交的 GSAP 页面动效和路由容错改动。

## 3. 功能补全范围

### 3.1 首页

- 调整问候语、摘要和“浏览项目”的排版层级。
- 将“可用积分”移到首页首屏右侧信息区。
- 删除“所有购买均为本地 mock 流程，不发生真实支付。”文案。
- 保持可用项目和最近订单的数据加载、错误、空状态与跳转能力。
- 在 320、768、1024 和 1440 px 下保持合理布局。

### 3.2 号码管理

- 增加号码搜索。
- 增加项目和套餐筛选。
- 补齐“全部、使用中、已过期”状态筛选；状态只使用后端明确返回值。
- 增加全部、使用中和已过期号码摘要，不按前端时间阈值推导业务状态。
- 增加随机取码入口；真实接口接入前使用 mock service，并明确演示状态。
- 保留分页、加载、空状态、错误和重试。

### 3.3 短信收件箱

- 增加手动刷新和可控的自动刷新。
- 增加全部、未读、已读筛选。
- 增加项目、号码和关键词筛选。
- 增加“全部已读”。
- 保留单条标记已读、验证码展示、分页和错误恢复。

### 3.4 订单

- 增加订单详情前端路由和页面。
- 接入现有 `GET /orders/:id` 接口。
- 从订单列表和首页最近订单进入详情。
- 展示订单号、项目、套餐、数量、积分、状态、创建时间和关联号码。

### 3.5 积分

- 保留余额和积分流水。
- 补充与订单详情之间的可追溯跳转（以现有数据字段为准）。
- 充值入口在真实接口提供前仅展示不可用状态，不模拟真实充值。

### 3.6 账户设置

- 增加亮色/暗色主题切换。
- 增加中文/英文界面切换框架。
- 增加修改密码表单；真实接口提供前使用 mock service，不改变真实凭据。
- 保留账户资料和退出登录。

## 4. 数据源策略

| 能力 | 当前数据源 | 后续替换 |
|---|---|---|
| 登录、首页、项目、下单 | 本地 API + PostgreSQL | 公司客户 API |
| 订单、号码、积分、短信 | 本地 API + PostgreSQL | 公司业务 API |
| 订单详情 | 现有本地 API | 公司订单 API |
| 高级筛选、随机取码 | mock service | 公司号码 API |
| 短信自动刷新、批量已读 | mock service / 现有数据组合 | 公司短信 API |
| 主题、语言 | 前端偏好状态 | 可选账户偏好 API |
| 修改密码 | mock service | 公司账户 API |

## 5. 实施顺序

1. 首页首屏排版调整。
2. 订单详情路由与页面。
3. 号码管理筛选、摘要和随机取码。
4. 短信筛选、刷新和全部已读。
5. 账户主题、语言和密码。
6. 全量响应式、无障碍和浏览器流程复验。

## 6. 验收标准

- 每个新增行为先有失败测试，再完成实现。
- `npm test`、`npm run typecheck` 和 `npm run build` 全部通过。
- 页面具备 loading、empty、error 和 retry 状态。
- 键盘可操作，交互控件有可访问名称和清晰焦点。
- 320、768、1024 和 1440 px 无阻塞性横向溢出或文本重叠。
- mock 能力在界面和代码边界中明确标识，不能被误认为真实公司服务。

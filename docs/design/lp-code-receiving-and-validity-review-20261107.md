## 1. 两种商品

| 商品 | 客户权益 | 成功与结束 |
| --- | --- | --- |
| 一次性接码 | 指定号码＋指定平台的一条有效验证码 | 号码成功交付起15分钟内，PC实际收到有效首码即成功；完整窗口核对无有效码才失败；未核对完整继续等待 |
| 7／30天平台收码托管 | 从实际交付起完整168／720小时的平台收信服务 | 成功交付即生效，沿现有收信能力和限频，不增加本地总条数限制；客户服务截止后不再延长 |

直接API收信、LP站内展示是接入方向，不依赖当前不可用的项目链接创建API。一次性等待窗口是分钟权益，不用“0天套餐”代替。正式售价仍待讨论，不据本文件生成报价或修改已有价格。

## 2. 三种期限

| 期限 | 含义与约束 |
| --- | --- |
| 号码资源有效期 | PC资源实际可用期；销售时及实际交付时均须足额覆盖承诺，不能把将来可能续期当作已续期 |
| 项目取码链接有效期 | 某条上游链接的访问期限；当前销售不依赖创建此链接 |
| LP客户服务期 | 一次性15分钟，或交付起完整168／720小时；资源续期不自动延长既有权益 |

资源只剩20天不能交付完整30天托管，也不能静默截短为20天。上游授权失效、资源失效、客户服务截止是不同事实。本站不自动调用PC买号、续号或划拨。

“永久禁售”是本站约束，不保证第三方平台永不解绑或运营商永不回收号码。失败可再售是用户明确决定，不因前一客户可能触发迟到短信另加禁售政策。

## 4. 一次性生命周期与资金

1. 客户选择平台与商品；订单按成交价格冻结积分，并暂占实际号码＋平台。
2. 号码成功交付时记录不可变开始/截止时间。只接收属于本次号码、可信平台及该窗口的新消息，订单前的旧短信不能完成订单。
3. 按后台平台专用规则识别到窗口内有效首码时，原子保存首码归属、成功结果、扣分与永久售出事实。重复拉取同一消息不新增交付或重复扣分。
4. 到15分钟但未能证明整个接收窗口已核对完整，继续WAITING；页面可显示“窗口已结束，结果核对中”。不再延长原窗口，也不提前恢复可售。
5. 完整核对确认无有效码后，才FAILED、全额释放冻结并解除临时占用。重新销售仍须检查资源、授权、平台及正常库存可用性。
6. 成功后历史读取只返回已交付首码；后续短信不成为这个一次性订单的新交付。客户是否已在第三方成功注册/登录不是LP可自动检测的条件。

| 场景 | 结果 |
| --- | --- |
| 第3分钟PC收到有效首码 | SUCCESS、结算、保存首码、永久禁售该组合 |
| PC在14:59收到有效码，LP在15:02同步 | SUCCESS，依PC接收时间，不以LP入库时间判失败 |
| 15分钟到但分页、网络或消息归属仍未核对完成 | WAITING、继续冻结及占用，等待真实核对证据 |
| 完整窗口确认无有效码 | FAILED、全额释放；仍满足库存条件才允许再售 |
| 成功消息重复同步或用户重复刷新 | 复用原交付与资金事实 |
| 成功后出现新短信 | 不给原一次性订单新增取码权益 |
| 客户在第三方使用验证码被拒绝 | 转人工售后，不自动重开窗口或补取 |

业务状态与订单分配/履约状态分别存储；不能仅将已交付号码的订单标成COMPLETED就认为首码已成功。取消、拒码等售后不自动扩展成未经确认的退款政策。

## 5. 托管交付与永久销售记录

托管保留原有收信能力，不增加本地总短信数限制，不承诺无限频率或永久服务。开始和截止时间由实际交付记录决定，按168／720小时计算；资源不足时明确拒绝交付，不截短承诺、不自动续号。

成功销售的实际号码＋平台应具有独立持久事实：客户服务到期、关闭allocation、上下架、重新同步或号码续期均不清除。库存查询、并发分配和管理入口必须共同遵守该事实；同一号码的其他平台仍按各自约束经营。历史来源与已成交记录保留，不重新解释历史金额或删除来源。

原客户延长、续号成本和正式价格仍须另外确定，不因此新增自动续费、自动续期或永久收码权益。

## 6. 平台、有效码与完整窗口的证据

短信必须可靠关联到上游连接、实际号码、所购平台、订单/服务，并保留稳定上游ID及接收时间。平台归属和有效验证码识别是两项条件：知道发送者来自某平台，并不代表某条通知或营销短信就是验证码。

真实PC公开契约目前没有确认LP自营的平台项目映射及接收窗口完整保证。既有`PC_PLATFORM_PROJECT_UNCONFIRMED`拒绝路径继续保留，不能让通用4–8位数字提取成为真实跨客户隔离保证。

`upstream_accounts.message_checkpoint`只用于按上游创建时间分页断点恢复。`completedThrough`、`scan=null`或`hasMore=false`都不证明“PC实际接收时间窗口已完整核对”：消息可能较晚创建，也可能已持久化却仍处于UNMATCHED／FAILED／QUARANTINED。不得据此自动失败、退分或释放库存。核对证据须说明精确连接、号码、平台、原窗口及消息归属处理结果；证据缺失继续WAITING。
